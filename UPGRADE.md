# UPGRADE FROM `1.x` TO `2.0`

The `2.x` version of the plugin requires **Sylius 2.3** (Symfony 6.4/7.4, Doctrine ORM 3 / DBAL 4).

## 1. Update the dependencies

```bash
composer require sylius/sylius:^2.3 arobases/sylius-rights-management-plugin:^2.0
```

## 2. Routing

The admin routes are now generated by the `sylius.resource` loader. Route **names** are unchanged
(`arobases_sylius_rights_management_plugin_admin_role_*`), only the URLs changed
(`/admin/role` → `/admin/roles/`, `/admin/role/{id}/update` → `/admin/roles/{id}/edit`...).

You can use the admin path parameter for the prefix:

```yaml
# config/routes/arobases_sylius_rights_management_plugin.yaml
arobases_sylius_rights_management_plugin_admin:
    resource: "@ArobasesSyliusRightsManagementPlugin/Resources/config/admin_routing.yml"
    prefix: '/%sylius_admin.path_name%'
```

## 3. Templates

* The Sylius 1.x template override `templates/bundles/SyliusAdminBundle/AdminUser/Form/_generalInfoExtended.html.twig`
  is no longer used: remove it. The role field is now rendered through Twig hooks
  (it replaces the Sylius Plus "Roles" placeholder of the administrator form).
* The `@ArobasesSyliusRightsManagementPlugin/Admin/Role/form.html.twig` template has been removed, the role form
  is rendered with the `arobases_sylius_rights_management_plugin.admin.role.(create|update).content.form.sections` hooks.

## 4. Admin user entity

Doctrine annotations are not supported anymore by Doctrine ORM 3: map your `AdminUser` entity with attributes.
`AdminUserTrait` provides the attribute mapping of the `role` relation.

```php
#[ORM\Entity]
#[ORM\Table(name: 'sylius_admin_user')]
class AdminUser extends BaseAdminUser implements AdminUserInterface
{
    use AdminUserTrait;
}
```

## 5. Database

The `routes` and `excludedRoutes` columns of the `arobases_sylius_rights_management_right` table
were stored with the Doctrine `array` type (serialized PHP), which has been removed from DBAL 4.
They now use the `json` type.

The existing serialized values can not be converted to JSON by the database, so empty them before migrating
(they are regenerated from the configuration by the `arobases:right:create-admin-right` command,
the rights already given to the roles are kept):

1. Generate the migration: `bin/console doctrine:migrations:diff`
2. At the beginning of the `up()` method of the generated migration, add:
   ```php
   $this->addSql('UPDATE arobases_sylius_rights_management_right SET routes = NULL, excludedRoutes = NULL');
   ```
3. Run it: `bin/console doctrine:migrations:migrate`
4. Regenerate the routes of the rights: `bin/console arobases:right:create-admin-right`

## 6. Default rights

The default rights (`right_management.yaml`) have been updated for the Sylius 2 admin routes:

* removed the Sylius 1.x only routes (`sylius_admin_ajax_generate_*_slug`, `sylius_admin_get_product_attributes_*`,
  `sylius_admin_get_attribute_types`, `sylius_admin_ajax_taxon_*`, `sylius_admin_get_payment_gateways`);
* the "Products" right does not give access anymore to the attributes, options, association types and reviews
  (they have their own rights);
* the "Orders" and "Payments" rights do not give access anymore to the payment methods;
* the "Customers" right now gives access to the shop user deletion (`sylius_admin_shop_user_*`).

The dashboard, the security pages, the live components (`sylius_admin_live_component`)
and the autocomplete (`sylius_admin_entity_autocomplete`) routes are always granted to the administrators.

## 7. Code changes

* `RightAdapter` now receives the rights configuration array instead of the service container.
* `Sylius\Component\Resource\Model\*` interfaces have been replaced by `Sylius\Resource\Model\*`.
